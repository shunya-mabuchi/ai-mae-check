# AIまえチェック 0.2.0 提出候補

0.2.0はChrome Web Storeへの提出候補です。現在の一般公開版は0.1.2であり、0.2.0の公開確認前にGit tagやGitHub Releaseは作成しません。

## 主な変更

- 公開サイトをVite MPAへ再構築し、Reactはミニデモへ限定
- 公開サイト、Options Page、拡張モーダルへReact Aria Componentsを導入
- 共通デザイントークン、Tailwind CSS 4、Biomeを導入
- WebLLM実行系を明示操作まで遅延ロード
- ルールベース検出、PolicyDecision、ContextBuilder、サイトAdapter、評価fixtureを整理
- 対応するテキスト系ファイルの添付前チェックを追加
- 署名付き静的ルール配信を `/rules/latest.json` へ統一
- Chrome拡張E2E、公開文書、サイズ予算、ストア提出物QAを強化
- AI文脈チェックの採用・人事情報を医療情報と分離し、安全化時に `[人事情報]` と表示するよう修正
- WebLLMを `Llama-3.2-1B-Instruct-q4f32_1-MLC` の単一モデルへ統一
- Options Pageに「標準 / 低負荷」を追加し、低負荷では同じLlamaのcontext window、入力長、出力長、候補数を削減
- GPUメモリ不足・デバイス喪失後の無条件な即時再試行を停止し、失敗時もルールベース検出とローカル補助候補を維持

## プライバシー設計

- 貼り付け本文、送信本文、添付前に読み取った対応ファイル本文を永続保存しない
- 外部LLM APIや開発者のサーバーへ本文を送信しない
- `chrome.storage.local` にはユーザー設定と検証済みルールキャッシュだけを保存する
- WebLLMの初回利用時にはローカル推論用モデルファイルを取得する場合がある

## 既知の制限

- 本ツールは情報漏洩を完全に防ぐものではなく、検出漏れや誤検出が発生する可能性がある
- WebLLMは補助的な候補提示であり、WebGPU非対応環境では利用できない場合がある
- macOS / LinuxのWebLLM実機確認は、利用可能な実機がないためIssue #433で継続する
- ファイルチェックは対応するテキスト系ファイルが対象で、PDF、docx、xlsx、画像・OCRは対象外
- 対象サイト独自のドラッグ&ドロップやクリップボード経由のファイル添付は動作保証の対象外
