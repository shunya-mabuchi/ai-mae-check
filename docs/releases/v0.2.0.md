# AIまえチェック v0.2.0

0.2.0は2026年8月5日にChrome Web Storeへ審査送信し、2026年8月8日に一般公開を確認しました。

## 主な変更

- 公開サイトをVite MPAへ再構築し、Reactはミニデモへ限定
- 公開サイト、Options Page、拡張モーダルへReact Aria Componentsを導入
- 共通デザイントークン、Tailwind CSS 4、Biomeを導入
- ルールベース検出、PolicyDecision、ContextBuilder、サイトAdapter、評価fixtureを整理
- 対応するテキスト系ファイルの添付前チェックを追加
- 署名付き静的ルール配信を `/rules/latest.json` へ統一
- ChatGPT / Claude / Gemini / Perplexity adapterのE2E、公開文書、サイズ予算、ストア提出物QAを強化
- AI文脈チェックの採用・人事情報を医療情報と分離し、安全化時に `[人事情報]` と表示するよう修正
- AI文脈チェックをTransformers.js + ONNX Runtime WebのCPU/WASM経路へ一本化
- `jiting/xlm-roberta-ner-japanese_onnx` q8で人名、組織名、場所、施設、製品、イベントの候補を抽出
- `sirasagi62/ruri-v3-30m-ONNX` q8で契約、人事、法務、財務、社内、未公開、機密文脈の候補を分類
- NERとRuriをWorker内で並列準備し、片方が失敗しても利用可能な候補とルールベース結果を維持
- WebGPU、生成LLM、E5への実行時依存とモデル選択UIを削除
- 設定画面に固定モデルID、CPU/WASM実行、初回取得容量が320MBを超える場合があることを明記
- 明確な業務語句とモデル分類が競合した場合、具体的な語句候補を優先して誤分類と重複表示を抑制
- CPU/WASMローカルAIの処理を責務別モジュールへ分離し、保守性とテスト容易性を改善

## 役割分担

- メール、電話番号、APIキー、秘密鍵などの確定情報は `packages/core` のルールベース検出を優先する
- 固有名詞は日本語NER、曖昧な業務文脈はRuriの類似度分類で追加候補を提示する
- AI候補は安全判定を確定せず、ユーザーが安全化対象を選ぶ
- 送信可否はPolicy Decisionがルールベース結果を中心に判定する

## プライバシー設計

- 貼り付け本文、送信本文、添付前に読み取った対応ファイル本文を永続保存しない
- 外部LLM APIや開発者のサーバーへ本文を送信しない
- `chrome.storage.local` にはユーザー設定と検証済みルールキャッシュだけを保存する
- AI文脈チェックの初回利用時にはローカル推論用モデルファイルを取得する場合がある
- モデル取得後はブラウザキャッシュを利用する

## 既知の制限

- 本ツールは情報漏洩を完全に防ぐものではなく、検出漏れや誤検出が発生する可能性がある
- NERとRuriは補助的な候補提示であり、最終的な安全判定ではない
- 初回は合計320MBを超えるモデル関連ファイルを取得する場合があり、回線、保存容量、CPU、メモリの条件によって完了できない場合がある
- AI文脈チェックが失敗してもルールベース検出は継続する
- macOS / Linux実機は利用可能な端末がないため未確認
- ファイルチェックは対応するテキスト系ファイルが対象で、PDF、docx、xlsx、画像・OCRは対象外
- 対象サイト独自のドラッグ&ドロップやクリップボード経由のファイル添付は動作保証の対象外
