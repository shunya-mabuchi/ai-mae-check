# 公開サイト再設計リファレンス

## 位置づけ

このディレクトリの画像は、AIまえチェックの公開サイトとミニデモを再設計するための視覚仕様です。

画像生成による文言の揺れや細かな描画誤差が含まれる可能性があります。実装では、本書、README、プライバシーポリシー、Chrome Web Store掲載文の日本語を正とします。

## 画像

1. `01-hero-desktop.png`: 1440pxのヒーローと検出対象への遷移
2. `02-workbench-desktop.png`: デスクトップ版DemoWorkbench
3. `03-lower-desktop.png`: 仕組み、プライバシー、技術、導入CTA、フッター
4. `04-mobile-390.png`: 390pxでの情報順序とレスポンシブ構成

## デザインコンセプト

「送信前の落ち着いた確認レイヤー」を中心にします。強い警告を連続させるセキュリティ製品ではなく、文章を送る直前に立ち止まり、自分で確認できる道具として表現します。

## 情報の優先順位

1. AIまえチェックはChrome拡張である
2. AIへ送る前に消し忘れを確認できる
3. Chromeへ追加できる
4. 実際の拡張画面
5. 検出対象
6. ミニデモ
7. ブラウザ内処理と保存しない設計
8. 技術と補助リンク

## ヒーロー

- H1は「そのまま送らない。」
- 主CTAは「Chromeに追加」
- 副CTAは「デモを試す」
- 実際の拡張画面を本文より大きく見せる
- 第一ビューポートに次のセクションの一部を見せる
- 外部LLM APIへ本文を送らないことを短く添える
- 装飾用のeyebrow、pill、fake metricは置かない

## DemoWorkbench

デスクトップでは次の3領域を横に並べます。

1. 送信前の文章
2. 検出結果と選択
3. 安全化後プレビュー

モバイルでは同じ順番で縦に並べます。操作ボタンは44px以上の操作領域を持ち、長い日本語を無理に一行へ押し込みません。

検出項目はチェックボックスで安全化対象を選択できます。危険度だけを大きな数値で見せず、何が検出され、どの表現へ変わるかを中心にします。

## セクション構成

- ヒーロー
- 主な検出対象
- DemoWorkbench
- 送信前確認の5ステップ
- 本文を保存しない設計
- 技術構成
- Chrome拡張導入CTA
- フッター

すべてのセクションをカードで囲みません。全幅のband、rail、list、unframed layoutを使い、カードは個々の検出項目や実際のツール面に限定します。

## 色

- 背景: 白とクールなごく薄いneutral
- 本文: charcoal
- primary: emerald
- informational: blue
- critical/high: red
- medium: amber
- low: blueまたはneutral

赤、黄、緑は意味のある状態だけに使います。背景をcream、beige、brown系で統一しません。

## 形状

- 角丸は原則6pxまたは8px
- 大きな外枠に過剰な角丸を使わない
- 影は製品画面や前面に出るUIだけに限定する
- 境界線は1px
- UIをカードの中へさらにカードとして入れない

## タイポグラフィ

外部フォント取得を必須にせず、次のsystem font stackを基本とします。

```css
font-family: Inter, ui-sans-serif, system-ui, -apple-system,
  BlinkMacSystemFont, "Segoe UI", "Hiragino Sans", "Yu Gothic",
  Meiryo, sans-serif;
```

hero-scaleの文字はH1だけに使います。DemoWorkbench、Options、拡張モーダルでは小さく密度のあるUIタイポグラフィへ切り替えます。

## レスポンシブ

### 1440px

- 最大コンテンツ幅は1200px前後
- ヒーローはコピーより製品画像を大きくする
- DemoWorkbenchは3ペイン
- 次のセクションが第一ビューポート下端に少し見える

### 390px

- ナビゲーションはアイコンボタンで開閉する
- ヒーローコピー、CTA、製品画面の順に並べる
- 検出対象は2列またはcompact list
- DemoWorkbenchは入力、結果、出力の順に積む
- 5ステップは縦rail
- フッターリンクは折り返しても重ならない

## アクセシビリティ

- 本文と背景はWCAG AA相当のコントラストを目標とする
- 色だけで危険度を伝えない
- アイコンボタンには日本語のaccessible nameを付ける
- focus-visibleを消さない
- CheckboxとRadioはラベル全体を操作可能にする
- Dialogには見出しを付ける
- 読み上げ順とDOM順を一致させる

## 実装レビュー

実装後は1440pxと390pxでスクリーンショットを撮り、次を比較します。

- 第一CTAが最も目立つか
- Chrome拡張が本体だと分かるか
- カードが増えすぎていないか
- 検出項目と安全化後の対応が追えるか
- 高リスク色が装飾に使われていないか
- 長い日本語が切れていないか
- モバイルで操作順が自然か
- privacyとsupportがJavaScriptなしでも読めるか

### 2026-08-02の確認結果

1440pxと390pxの実ブラウザー表示を参照画像と比較し、次を確認しました。

| 比較点 | 実装判断 |
| --- | --- |
| 第一CTA | 緑の「Chrome Web Storeで追加」をヒーロー内で最も強い操作にし、デモはsecondaryへ下げた |
| 本体の見え方 | ヒーローと下部CTAの双方でChrome拡張が本体だと明記した |
| 製品画像 | 生成画像をそのまま使わず、実際の拡張モーダル画面へ差し替えた |
| 第一ビュー | 1440pxでは製品画面をコピーより大きくし、画面下端に次の検出対象セクションを見せた |
| カード密度 | カードは検出対象とミニデモの操作面へ限定し、仕組み・プライバシー・技術はbandとlistで構成した |
| 状態色 | 赤・黄・青はリスク表示だけに予約し、通常の導線と背景はemeraldとneutralで統一した |
| 390pxの順序 | コピー、CTA、製品画面、検出対象、入力、結果、安全化後出力の順に縦積みした |
| 文字と幅 | 390pxで横スクロールがなく、48pxのH1と長い日本語が切れないことを確認した |
| JavaScriptなし | Playwrightでprivacyとsupportの本文・見出し・主要リンクが読めることを確認した |

ミニデモはIssue #493でReact Aria Componentsへ移行し、デスクトップ3ペイン・モバイル縦積み・キーボード操作を実装しました。WebLLMの遅延ロード境界はIssue #494で続けます。
