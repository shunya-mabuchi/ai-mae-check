# WebLLM 実機確認メモ

WebLLMは、正規表現だけでは拾いにくい文脈上の注意候補をブラウザ内で確認するために使います。外部LLM APIや開発者の推論サーバーは使いません。

端末別、OS別、Chrome状態別の確認結果は [WebLLM対応環境とモデル互換性マトリクス](webllm-compatibility-matrix.md) の形式で記録します。IssueやPRへは、ユーザー本文、実APIキー、実トークン、実在の個人情報、placeholderMapを貼らないでください。

## 成功時

確認観点:

- AI文脈チェック開始時に「ローカルAIモデルを準備しています。初回のみ時間がかかる場合があります。」が表示される
- 初回はモデルファイル取得に時間がかかる場合がある
- モデル取得後はブラウザキャッシュやブラウザ管理下の保存領域を利用する
- 候補がある場合は、顧客名候補、人名候補、案件名候補などが「候補」として表示される
- 候補なしの場合は「安全を保証するものではありません」と表示される
- WebLLM候補は自動で確定扱いせず、ユーザーが確認できる

## WebGPU非対応時

表示される想定メッセージ:

> このブラウザまたは端末ではAI文脈チェックを利用できません。ルールベースの検出は引き続き利用できます。

確認観点:

- ルールベース検出は利用できる
- マスク・安全化の操作は継続できる
- エラーメッセージにユーザー本文を含めない
- モデル変更で解消しない場合があることを案内する

## GPU実行中断・メモリ不足時

標準プロファイルの準備または推論中に `DXGI_ERROR_DEVICE_HUNG`、`Device was lost`、`insufficient memory` などが発生した場合は、同じページ内で無条件に再試行しません。GPUデバイスが失われた状態で再初期化を重ねることを避け、ルールベース検出とローカル補助候補を維持します。

表示される想定メッセージ:

> AI文脈チェックを実行できませんでした。ルールベースの検出結果は引き続き利用できます。

ブラウザ内の補助候補がある場合:

> AI文脈チェックは完了できませんでしたが、ブラウザ内の補助検出で注意候補を表示しています。

GPU負荷が厳しい環境では、拡張機能のOptions Pageで「WebLLMによるAI文脈チェック」>「実行負荷」>「低負荷」を選びます。対象サイトのタブを再読み込みしてから実行すると、同じGemma 3 1Bモデルを小さいcontext window、入力長、出力長、候補数で初期化します。

確認観点:

- WebGPUアダプタ未取得時は不要なモデル再試行をしない
- GPUデバイス喪失後に同じページ内で無条件な即時再試行をしない
- ページを閉じる、または再読み込みするときに旧Workerとruntimeの破棄を試みる
- 実行失敗時は、ルールベース検出とローカル補助候補を維持する
- 低負荷設定でもモデルIDはGemma 3 1Bのままで、context window、入力、出力、候補数が削減される
- AI文脈チェックが完了した、または安全であるとは表示しない
- エラー表示や診断メモにユーザー本文を含めない
- 画面に表示されたエラー分類、モデルID、推論プロファイルだけを診断記録へ含める

## 0.1.2とのA/B確認

同じ通常Chrome環境で、公開済み0.1.2と現在版を次の順で比較します。比較にはこの文書のダミー文だけを使い、ユーザー本文は記録しません。

1. Chromeのバージョン、OS、GPU名、GPUドライバー、`chrome://gpu` のDawn Infoを記録する
2. 0.1.2で初回ロード、候補表示、2回目の実行結果を確認する
3. Chromeを完全終了して再起動する
4. 現在版の標準プロファイルで同じ確認を行う
5. Chromeを完全終了して再起動する
6. 現在版の低負荷プロファイルで同じ確認を行う
7. 成功、候補なし、`webgpu`、`memory`、`worker` などのエラー分類だけを互換性マトリクスへ記録する

バージョン間でChrome、Dawn、GPUドライバーが異なる場合は、アプリ差分だけが原因とは断定せず、差分を備考へ明記します。

## モデル取得失敗時

表示される想定メッセージ:

> ローカルAIモデルの取得に失敗しました。モデル配信元への接続がブロックされている可能性があります。ルールベースの検出結果は引き続き利用できます。

確認観点:

- Hugging FaceやGitHub rawなどのモデル配信元への接続制限を確認する
- 広告ブロッカー、セキュリティソフト、社内ネットワーク制限の影響を疑う
- ルールベース検出結果が消えない
- エラーにユーザー本文を含めない

## 保存領域不足時

private browser / シークレットモードでは、モデル保存領域が不足し `QuotaExceededError` が出る場合があります。

確認観点:

- 通常ウィンドウで再試行する
- Chrome DevTools > Application > Storageから該当サイトデータを削除して再試行する
- ディスク空き容量を確認する
